UI & navigation — what to fix, and three ways to fix it

Categories has no desktop or tablet nav entry

Sidebar.tsx lists Home / Accounts / Activity / Budgets / Reports / Settings. /categories is only reachable from the mobile More sheet or by typing the URL.

The same global month cycle has four different controls

CycleStepper in the mobile header, a bespoke pill stepper in DashboardPage, another in TransactionsPage, and CycleStepper again on Budgets — same state, four shapes and positions.

“More” is a junk drawer, and it owns account actions

One tab hides three destinations plus dark mode and sign out. Theme toggle exists only there — desktop users can't switch theme outside Settings.

No global search, though the machinery is already installed

cmdk and ui/command.tsx ship in the bundle but only power AccountCombobox. Search is per-page and text-only; there is no way to jump to an account or a screen.

Tablet (768–1023) gets the least support

The mobile header is md:hidden and the detail pane is lg:-only, so 768 has no app bar, no avatar, no entry-detail pane — an 80px rail and a page, nothing else.

176px of dead scroll under every mobile page

AppLayout pads main by 176px + safe-area to clear an 80px nav and a 56px FAB. The FAB also disappears on /settings and whenever a sheet is open.

Three navigation models below, each shown at 1920 / 768 / 390 on Home. 2A is the smallest change, 2B the biggest, 2C the most Material-3-native. The recreation of today's UI is in 1A.

2A

Grouped rail + one global bar

Keeps the M3 drawer. Adds section groups, Categories, a theme toggle, and a single persistent period + ⌘K bar shared by all three breakpoints.
