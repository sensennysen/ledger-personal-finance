| ID | Severity | Issue | Suggested fix |
| --- | --- | --- | --- |
| REV-001 | High | Loan calculation RPCs can disclose another user's financial amounts | Add a migration that makes API-facing calculations SECURITY INVOKER with RLS, or moves privileged helpers into an unexposed private schema. Revoke EXECUTE explicitly from PUBLIC and anon, and grant only intended roles. Require ownership in any exposed definer wrapper. |
| REV-002 | High | Late profile responses can restore a signed-out user's data | Track an auth/request generation and check it before every state update, cache write and migration side effect. Clear profile immediately on user changes. Cancel or discard outstanding reads when signing out. |
| REV-003 | High | Card payment tracking is neither atomic nor safe under concurrent payments | Move transfer creation, unique payment linkage and statement updates into one idempotent SECURITY INVOKER RPC or database trigger. Lock the card row and update the paid amount atomically. Use the same operation for manual, imported and recurring payments. |
| REV-004 | High | Conflict detection can overwrite newer server edits | Capture the original server revision in each queued mutation. Apply a conditional update/delete against that revision in one server operation. Retain the item when verification fails and surface a retryable error. Reserve bypass for an explicit Keep mine choice. |
| REV-005 | High | Imported offline transactions do not retain their optimistic IDs | Generate one ID per imported row and reuse it in the optimistic transaction, queued insert and all follow-up writes. Make replay idempotent by reconciling an existing ID and its owner/payload rather than treating every duplicate-key response as a new failure. |
| REV-006 | High | An edit made while a queued insert is saving can be lost | Version queued items and acknowledge only the version actually sent. Preserve a newer version as an update after the insert succeeds, or prevent editing the item while in flight with a clear UI state. |
| REV-007 | Medium | Pending receipts are handled only for queued inserts | Represent attachment upload as a durable job independent of insert/update mode. Resolve pending files for both operations, and enqueue recovery when an online upload falls back to local storage. Do not store an unresolved marker as a completed server attachment. |
| REV-008 | Medium | A connection failure after receipt upload can lose the attachment reference | Persist the resolved storage path before attempting the row mutation. Retain the local blob until that path is durably recorded. Preserve the resolved payload on thrown errors and add cleanup for abandoned uploads. |
| REV-009 | Medium | The shared queue has no cross-tab coordination | Use a transactional IndexedDB queue and coordinate drains across tabs with Web Locks or a persisted lease. Broadcast queue changes. Keep database writes idempotent because a browser lock alone cannot guarantee exactly-once delivery. |
| REV-010 | Medium | Optimistic changes are applied before the queue is durably written | Persist the queued mutation before announcing or applying optimistic success. Return a structured storage error and roll back any optimistic state if persistence fails. Use IndexedDB and report unavailable durable storage. |
| REV-011 | Medium | Transaction requests can finish out of order after filters change | Associate displayed data with its query key. Discard responses whose request generation/key is no longer current, and pass cancellation checks into readAllPages. Reuse a small tested request-state abstraction across affected hooks. |
| REV-012 | Medium | Reloading while online does not automatically drain pending transactions | Drain on authenticated startup when online and pending items exist. Schedule a bounded retry for transient failures and check readiness on focus/visibility changes. Coordinate startup with registration of durable follow-ups. |
| REV-013 | Medium | Mutation notifications do not refresh all affected data | Introduce a shared entity/query store with explicit invalidation for transactions, accounts, budgets, goals and card payments. Invalidate or reconcile all affected keys after server writes and queue drain. Reuse one subscription contract instead of cache-only refresh events. |
| REV-014 | Medium | Opening a list offline without a cached result leaves loading active | Resolve offline-without-cache as an explicit unavailable state through resolveLoadState. Clear loading, name the missing offline data and retry when connectivity returns. Share this policy across list hooks. |
| REV-015 | Medium | Several history/export reads still stop at the API row cap | Use readAllPages with a deterministic total order for every potentially unbounded source, including these export reads. Batch large ID filters or replace them with joined server queries when URLs become too large. |
| REV-016 | Medium | The account export omits archived accounts | Add an explicit includeArchived/export read mode or a dedicated complete account query, preserving the active-only behavior for normal account pickers. Keep the export dataset separate from display-only filtering. |
| REV-017 | Medium | Cash-flow forecasts add native currency amounts to a converted balance | Move the forecast calculation to a pure src/lib helper and convert each occurrence into the base currency with amountInCurrency/sumConverted. Exclude and identify currencies lacking rates, including item totals and sort order. |
| REV-018 | Medium | Savings-goal linked contributions ignore currency conversion | Calculate contributions in the goal currency using the shared conversion helper. Keep missing-rate currencies visible and exclude them from the numeric total until a rate is available. |
| REV-019 | Medium | Savings contributions overwrite concurrent increments | Add a SECURITY INVOKER RPC that locks the owned goal and increments current_amount in SQL. Give each contribution a unique operation ID for safe retries or record contributions as ledger rows. |
| REV-020 | Medium | A failed savings contribution closes the dialog without showing the error | Check error and errorDetail before closing the contribution dialog. Preserve the input and display a FormError or notification with a retry action, following the adjacent create/edit goal handlers. |
| REV-021 | Medium | Some user-owned references have no ownership guard | Add composite owner-scoped foreign keys or ownership triggers for every user-owned reference. Validate a payment's transaction, destination and amount relationship as well as its owner. Backfill or repair invalid links before validating constraints. |
| REV-022 | Medium | Bulk category changes can leave a subcategory attached to the wrong parent | Clear subcategory_id when changing the parent category unless an explicit mapping preserves it. Add a database guard requiring the selected subcategory to belong to the selected category, including subcategory reparenting paths. |
| REV-023 | Medium | An account currency can be changed without migrating its history | Prevent currency changes once transaction or financed-purchase history exists, in both the form and the database. If currency migration is a required feature, implement an explicit atomic conversion workflow with a recorded rate and audit trail. |
| REV-024 | Medium | All routes and heavy features load in the main JavaScript bundle | Lazy-load route pages with React.lazy and useful Suspense boundaries. Load PDF generation, charts and import editors when needed. Adjust service-worker precaching deliberately so deferred features do not all transfer during installation. Measure before choosing extra chunk rules. |
| REV-025 | Medium | Offline bulk imports repeatedly serialize the entire growing queue | Add a reusable enqueueMany operation that persists all rows in one transaction. Apply account deltas in one pass, update caches once and emit one notification. Use IndexedDB for larger durable batches. |
| REV-026 | Medium | CI validates migration syntax but not tenant isolation or financial concurrency | Add a focused database integration suite after migration application, using separate JWT/SQL roles and transaction connections. Cover anon and cross-user access, balance invariants, payment idempotency and concurrent writes. Add hook lifecycle tests for delayed reads and auth changes. |
| REV-027 | Low | The Supabase client lacks generated database types | Generate database types from the migration-applied local schema and use createClient<Database>. Derive entity DTOs and RPC arguments from them. Keep the fake client boundary small and typed rather than expanding any into application logic. |
| REV-028 | Low | Common entity hooks repeat reads and loading/cache policies | Share entity reads through a user-scoped query store or reusable read hook with request deduplication, key-aware state and consistent offline/error policy. Keep entity-specific business mutations outside the shared read abstraction. |
