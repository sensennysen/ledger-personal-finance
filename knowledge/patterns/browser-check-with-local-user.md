# Check UI in a real browser with a local test user
Earlier retros left layout unverified because sign-in is Google-only. It doesn't have to be.
**Why:** Phase 4 found nine layout bugs this way (truncated cells, an empty loan column, Home 166px too tall at 1920). The code-level checks all passed.
**How:**
1. `.env.local` points at local Supabase (`http://127.0.0.1:54321`). Create a user with the local service key: `POST /auth/v1/admin/users` with `email_confirm: true` and a password.
2. Seed rows for that user with `psql postgresql://postgres:postgres@127.0.0.1:54322/postgres`. Default categories exist on signup. Use the design's sample numbers.
3. Get a session: `POST /auth/v1/token?grant_type=password` with the anon key.
4. Drive `Google Chrome --headless=new --remote-debugging-port=…` over CDP with Node 22's built-in `WebSocket`. No installs are needed.
   - Set `localStorage['sb-127-auth-token']` to the session JSON on `/login`.
   - Set `Emulation.setDeviceMetricsOverride` for 390×844, 1280, 1920×1080.
   - Navigate, `Runtime.evaluate` measurements (`main.scrollHeight` vs `clientHeight`), then `Page.captureScreenshot`.
5. Wrap evaluated code in `(async () => { … })()`, since top-level await is rejected. For React inputs, set the value with the native setter, then dispatch `input` and `focusout`.
6. Keep the script and screenshots in the session scratchpad, not the repo. Delete the test user when done.
7. Simulate failures with CDP `Network.setBlockedURLs` (e.g. `*rest/v1/credit_card_payments*`); fetch then throws "Failed to fetch". Since LED-242 a blocked **first load** (nothing cached) surfaces in about 1 to 2 s; a read with the cache on screen still takes ~7 s, because supabase-js retries GETs there. Clear `ledger_cache:*` first when you want the fast path, and wait before asserting otherwise; writes fail at once. On a cold failure the profile banner shows too, with its own Retry: click the page's "Try again", not the first Retry button. Match buttons by exact `aria-label`: "Dismiss" also matches the PWA banner's "Dismiss install banner".
8. To check a download, stub `URL.createObjectURL` so it records the Blob, make `URL.revokeObjectURL` a no-op and set `HTMLAnchorElement.prototype.click` to record the `download` attribute. Then `await blob.text()`. Fetching the blob URL after the click fails, because the code revokes it synchronously. This caught a UTC-dated filename in LED-89.
9. To see a **skeleton**, hold the reads: `Fetch.enable` with `urlPattern`s such as `*/rest/v1/transactions*`, keep the `Fetch.requestPaused` ids while holding, and release them with `Fetch.continueRequest` when you want the loaded state. Two traps (LED-150): clear `localStorage` (except `sb-*`, theme and preferences) and IndexedDB first, or the cache renders the loaded page at once; and pump paused requests on a `setInterval` (calling `continueRequest` once after `release` misses requests made later, so "loaded" is still the skeleton). Add `setTimeout(() => process.exit(0), 100)` to the script's `finally`, since the interval keeps Node alive.
10. Measure a skeleton against its loaded page by element heights and tops (`getBoundingClientRect`), not by eye. The 8px that Categories moved (Tabs' `gap-2`) was visible only as `firstRowTop` 312 against 320.

11. **Bisect with a stub.** `Page.addScriptToEvaluateOnNewDocument` runs before the app. Stubbing `Element.prototype.scrollIntoView` showed in one run that the mobile tab strip moved Chrome's Tab starting point past the header (LED-155). Remove the script with `Page.removeScriptToEvaluateOnNewDocument`.
12. **Answer a write like the server would.** To see the error copy for a database code, `Fetch.enable` a pattern and `Fetch.fulfillRequest` a PostgREST-shaped body (`{code, message, details, hint}`, status 403 / 409 / 400) for non-GET requests. Reset `p.handlers` between cases or the first answer keeps winning. Blocking (`Network.setBlockedURLs`) only ever gives "Failed to fetch".
13. **Measure a list, do not eyeball it.** Install a `PerformanceObserver` for `longtask` and a rAF gap recorder, scroll the list's `main` to the end in steps, and log the longest task per step against the rows mounted. Do it on the Vite dev server and on `vite preview` of a production build: React's dev build is two to three times slower (LED-125: 1.26 s against 0.44 s at 2,000 rows). Read `performance.memory.usedJSHeapSize` and the DOM node count too.
14. **Compare the UI with SQL, not with itself.** Seed a known volume (2,000 rows, 1,500 expenses in a yearly budget), then compare each total on screen with a `psql` sum. Count the requests too: a `Network.responseReceived` handler on `/rest/v1/transactions` with the `Content-Range` header shows how many pages each route reads.
15. **Do not reload while offline.** `Network.emulateNetworkConditions` with `offline: true` fires the app's offline event, but a full navigation then loads nothing (no service worker on the dev server). Change the viewport or click through the app instead. To see "Syncing 1 of 3", hold the POSTs with `Fetch.requestPaused` and release them one at a time.
16. **Files and time zones.** `DOM.setFileInputFiles` takes an `objectId` from `Runtime.evaluate` and fills an `<input type=file>`. `Emulation.setTimezoneOverride` (`Etc/GMT+12`) proves a filename uses the local date, not UTC. `Emulation.setEmulatedMedia` with `prefers-reduced-motion: reduce` checks motion; count animations and transitions longer than 1 ms afterwards.
17. **Clicks in a scrolling dialog.** `scrollIntoView` in a dialog with smooth scrolling has not finished when the rect is read, so the click lands beside the button. Scroll, wait 300 ms, read the rect again, or call `.click()` on the element for a submit button.
18. **Seed data can lie to you.** A `like '% purchase #9%'` cleanup removed 120 seeded rows. Delete test rows by an id list or a marker column, and re-count before you rely on a number.
19. **The harness sets the theme after the first load.** A fresh headless Chrome resolves `system` as dark, so a screenshot taken right after `login()` may be dark. Call the theme setter, reload, then capture.
20. **`cn()`'s `twMerge` can hide the class you're querying for.** `cn('rounded-2xl border p-4', condition ? 'border-border' : 'border-2 border-primary')` renders the plain `border` token only in the true branch — `twMerge` drops it when `border-2` collides with it in the false branch, leaving `rounded-2xl p-4 border-2 border-primary` with no standalone `border` class. A `document.querySelectorAll('div.rounded-2xl.border.p-4')` selector built from reading the source literally will silently miss that state (LED-158: it matched the done step, not the incomplete one being tested). Select by stable content (a text match, `closest()` from a known label) instead of reconstructing a class list from a `cn()` call you haven't rendered.
21. **A one-off dashboard state can accidentally satisfy the thing you're testing.** Seeding one transaction to get a "row with text" to Tab to for a focus-ring check also marks the first-run checklist's transaction step *done*, replacing its buttons with a checkmark — which silently skipped the exact incomplete-state layout a sibling ticket needed to measure. When two checks need contradictory seed states (one item present vs. absent), seed and check the state that matters *before* seeding the state the next check needs, or use two separate users.

22. **Hold reads without CDP.** In the in-app browser, override `window.fetch` in the page: queue calls whose URL matches (`/rest/v1/` or one table), keep their thunks, release with `thunk()` later. Clear `ledger_cache:*` first, then navigate with the app's own links or `history.pushState` + `dispatchEvent(new PopStateEvent('popstate'))` (a reload would drop the override). Always restore `window.fetch` in a `finally`: a script that returns early leaves the hold in place and every later read hangs.
23. **Measure a shift with a marker, not by eye.** Take the `top` of a stable element below the thing under test, loading and loaded, and subtract. For "natural" height against stretched height in a grid, set `style.alignSelf = 'start'` on the card, read the height, then put it back.
24. **Things that tripped a script (LED-199 to 204).** `innerText` applies `text-transform`, so a heading styled uppercase must be matched case-insensitively. Base UI tabs ignore a bare `.click()`; dispatch `pointerdown, mousedown, pointerup, mouseup, click` after `focus()`. Recharts 3 draws x labels as `<text>` inside the surface, not under `.recharts-xAxis`; select by the label text. A user's `profiles.dashboard_widget_order` (jsonb) beats the `localStorage` order, so reorder through psql. An early `return` inside a script that patched `Storage.prototype.setItem` leaves the patch in place.
25. **Seeding and users with no service key.** The documented seed (`supabase/seed.sql`) only inserts, so it can be applied to a running local database with `psql -1 -f` when the demo user is missing. For a second user, insert into `auth.users` and `auth.identities` the way the seed does (`extensions.crypt(..., extensions.gen_salt('bf'))`); `handle_new_user()` creates the profile and the default categories. Delete the user at the end and check that its categories went with it.
26. **Offline, without a real network cut.** A reload offline loads nothing (item 15), so stub `Object.defineProperty(navigator, 'onLine', { configurable: true, get: () => false })`, open the form, then `delete navigator.onLine`. It proves the branch, not the browser, so say so in the retro.
27. **Prove a pre-paint script on a probe page.** Put a one-page HTML that loads only the script under `public/`, load it in an iframe after setting `localStorage`, and read the class and meta in the iframe's document. Switch the OS scheme with `resize_window`'s `colorScheme`. Delete the probe file afterwards.

28. **Every fresh context is a new device.** Anything Ledger keeps per browser runs again in each new Playwright context, so test it on purpose with two contexts, opened in parallel, and count rows in psql. LED-232 found the recurring generator posting every due row once per context; since LED-232 the database records it (`transactions.recurrence_next_posted`, set by `post_recurring_transaction`), and `ledger-recurring-generated` in `localStorage` is only a shortcut. To make a recurring row due, insert it with `recurrence_next_posted = false` and a date one interval back; to stop one posting, set the flag to true.
29. **The transaction form's labels do not name their comboboxes.** `getByLabel('Kind')` finds nothing in the entry sheet. Find the `label` by text, walk up to the first ancestor that holds a `[role=combobox]`, tag that, then pick from `getByRole('option')`.
30. **Sign in through the dev form.** On the dev server, `/login` has a "Sign in with email" form (`import.meta.env.DEV` only), prefilled with the seed's demo user. Click it in the browser pane instead of injecting a session. To test a first-load migration of browser data, set the `localStorage` key on `/login` before signing in (LED-257).
