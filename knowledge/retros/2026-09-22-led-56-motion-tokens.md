# LED-56 — Motion tokens

## Pattern
The eleven ad-hoc durations named in the spec don't all collapse into the six tokens 1:1 — `.animate-fade-up`'s 420ms isn't mapped to any of the six token values in the design doc's own replacement table (only `--dur-enter` absorbs two source values, 280 and 320). Left it as a literal rather than inventing a seventh token or silently changing its duration; the "cap the stagger at four steps" requirement (point 10) is what actually fixes the perceived problem with `animate-fade-up`, not a duration change.

Tailwind v4's `transition-colors`/`transition-opacity`/bare `transition` utilities compile with `transition-timing-function:var(--tw-ease,var(--ease-out))` — they fall back straight to the theme's `--ease-out` variable, not to `--default-transition-timing-function` (which exists in `theme.css` but isn't referenced anywhere in the compiled utility CSS in this Tailwind version). Overriding `--ease-out` in an unlayered `:root` block is therefore both necessary and *sufficient* to make the named curve the default for every unlabeled Tailwind transition in the app — no `--default-transition-timing-function` override needed; adding one is dead code. Verified by grepping the built `dist/assets/index-*.css` for the compiled utility rule before writing that conclusion into the codebase.

This does mean the ticket's mandated name `--ease-out` collides with Tailwind's own built-in theme variable of the same name (`cubic-bezier(0, 0, 0.2, 1)`, used by the `ease-out` utility class). Because our override lives in an unlayered `:root` rule and Tailwind's theme variables live inside `@layer theme`, cascade-layer precedence means our value wins for equal-specificity `:root` matches — confirmed live in the browser (`getComputedStyle(document.documentElement).getPropertyValue('--ease-out')` returned our curve, not Tailwind's). No code currently uses the bare `ease-out` utility class, so there's no present conflict, but a future `className="ease-out"` would silently get the branded curve instead of Tailwind's standard one.

Three components implement their own stagger-delay formula via an inline `style={{ '--anim-delay': ... }}` (`AccountsPage.tsx`, `BudgetsPage.tsx`, `CategoriesPage.tsx`), bypassing the `.anim-delay-1..8` CSS classes entirely. Capping the CSS classes at four steps doesn't touch these — each one needed its own `Math.min(idx * N, cap)` ceiling lowered separately. `CategoriesPage.tsx` wasn't in the original plan's file list; it only surfaced by grepping every `--anim-delay` producer rather than trusting the plan's file list as exhaustive.

## Decisions
- `animate-fade-up`'s 420ms base duration left un-tokenized (see above) — six tokens per the AC, not seven.
- `--default-transition-timing-function` override added during `/apply`, then removed during `/validate` after the compiled CSS showed it was unreferenced dead code; `--ease-out` alone drives the default via Tailwind's own fallback chain.
- `avatar.tsx`'s three `ring-2` sites (decorative avatar-stack borders, no `focus-visible:` prefix) excluded from the ring-width unification — not a keyboard focus indicator, out of scope for the accessibility problem the spec describes.
- Reduced-motion fix uses a blanket `*, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }` inside the query rather than enumerating `animate-pulse`/`animate-spin`/`animate-in` selectors individually — matches the design doc's own recommendation ("a blanket rule for `*` inside the query, with the colour transitions allowed back, covers the rest").

## Acceptance
- Six duration tokens replace the ad-hoc values: PASS. `--dur-instant/fast/base/enter/sheet/meter` defined in `src/index.css`, applied at every call site the design doc's replacement table names (`dialog`, `alert-dialog`, `dropdown-menu`, `popover`, `select`, `sheet`, `BottomNav`, `AppLayout`, `LoginPage`, `DashboardPage`, `DashboardCategoryPieCard`, `ReportsPage`, `BudgetsPage`). Verified live: `getComputedStyle(document.documentElement)` returns the exact token values.
- `--ease-out` is a variable and is the default: PASS, with the Tailwind name-collision caveat above logged as a backlog risk, not a defect.
- Reduced-motion blocks merged and expanded: PASS by code + compiled-CSS inspection (`dist/assets/index-*.css` shows one merged `@media (prefers-reduced-motion: reduce)` block). Not verified live via OS-level media emulation — no `prefers-reduced-motion` toggle tool was available in this session's browser automation; relying on the compiled-CSS check plus the design doc's own suggested pattern.
- Stagger caps at four steps: PASS — both the CSS class merge (`.anim-delay-4..8` → same value) and the three inline `Math.min(idx*N, cap)` sites (`AccountsPage`, `BudgetsPage`, `CategoriesPage`) were lowered.
- One ring width (`ring-3` everywhere): PASS for all 8 confirmed `focus-visible:ring-2` sites. Verified live by keyboard-Tabbing to `TopBar`'s avatar button and visually confirming the wider ring. `DashboardCategoryPieCard`, `DashboardPage`'s widget cards, `AccountsPage`'s account cards, `BudgetsPage`'s budget card, `TransactionsPage`'s template chip, and `LoanPurchaseTracker` were changed by code but not seen live — the test account has zero accounts/transactions/budgets (same first-run-checklist gap LED-54's retro hit), so those cards never render.
- `pnpm lint`, `pnpm exec tsc -b && vite build`, `pnpm test` (133/133 + `redesign.mjs`): PASS.
