# LED-144 · Login: Google button, one logo, install prompt, dark panel, label — retro (2026-09-26)

## What shipped
- **Google button** on `--google-surface / -line / -ink / -surface-hover` tokens (light: white, #747775, #1F1F1F; dark: #131314, #8E918F, #E3E3E3), glyph colours kept, disabled tokens kept. Tokens because `tests/hardcodedColors.test.mjs` rejects literals in components.
- **`LedgerMark`**: one inline SVG (`currentColor` L, `var(--primary)` dot), outline traced from `l-black.png` (Node script in the session scratchpad, 4x supersampled, 135 points) and compared side by side. Used by `LoginPage` and `TopBar`; `l-white.png` is deleted. `l-black.png` (manifest, favicon) was re-rendered from the SVG with the indigo dot, so the yellow-green dot is gone everywhere.
- **`useInstallPrompt`** (`beforeinstallprompt`, `appinstalled`, standalone) shared by `PWAInstallBanner` and the login page's "Returning here often? Install Ledger" panel.
- **Right panel** is `bg-muted` in light and `bg-background` in dark (was `bg-muted/40`).
- **"Signing in…"**: `/login` is outside `ProtectedRoutes`, so the page did render while `AuthContext.loading` (the first session lookup) was true, and the button read "Signing in…" and was disabled for that whole time. It now reads "Signing in…" only after a click (`isSigningIn`); it stays disabled during the lookup.
