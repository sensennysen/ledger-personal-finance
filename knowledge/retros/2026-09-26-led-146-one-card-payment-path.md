# LED-146 · One card-payment path and one prefilled loan-payment path — retro (2026-09-26)

## What shipped
- **A card payment is a transfer** (`rules/card-payment-is-a-transfer.md`). The 12a form submits `cardPaymentTransfer(values)`: type `transfer`, no category, rate 1. The database rejected the old "expense to a card", so from Accounts and Activity a card payment could not be saved before this.
- `useCardPayment().createWithStatement` wraps `createTransaction` in the layout, Activity and the account page. A transfer into a credit card then also inserts `credit_card_payments` and moves `statement_paid_amount` (`planStatementPayment`), with the LED-93 partial-failure Fix. Offline it saves the transfer and raises a partial notification instead of claiming the statement updated.
- The account pane's inline form (Pay from, amount, date, Record payment) is gone. "Pay this card" keeps Amount to pay, statement facts, last payment and history, and one **Pay card** button that opens the same dialog, amount filled with what is due.
- **Pay from and the description are filled for a locked card or loan.** The effect that did it never ran when the target was locked (`to_account_id` already set), so Accounts and Home opened with the first account of any type or currency and no description.
- Both loan **Make payment** buttons (header and sidebar) call `handleRecordPayment(nextLoanDeadline)`; the ticket named only the sidebar one.
- Account facts ("Where it went", "Account") sit in an "Account details" disclosure below `lg`.
- `TransactionRow` reads the target account's type through `inferTransactionKind`, as the form does. Transactions now select `type` on `to_account`; cached rows without it keep the historical loan reading.
- Card payments validate with `cardPaymentSchema` (no category rule), chosen by a resolver that reads `isCardPayment`.

## Decisions
- **Any transfer into a credit card counts as a payment**, including one made with the Transfer kind. Cross-currency credits use `amount x rate` for the statement.
- No migration. LED-114 (OD-2) still owns a card-payments category.

The sidebar button calls the same handler and was not clicked separately.
- (b) Both loan buttons open the same prefilled form: PASS live (1,000 on 2026-09-29 from each).
- (c) Account facts reachable at 390: PASS live (disclosure opens, Statement day shown).
- (d) `TransactionRow` decides from the target type: PASS in code and by `inferTransactionKind` tests; not looked at in a list with a loan repayment row.
- (e) Lint, build, test: PASS (617).
