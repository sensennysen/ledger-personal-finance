# Live sweep · accounts, home, loans, budgets, legal and login (LED-126) — retro (2026-09-26)

Tree tested: branch `epics-8-13-phase-12` at `6202fbb` (tip of phase 11 plus the two earlier sweep retros; no source changed). Lint, build and all 666 tests were green on `4ab1888` before the phase.

## Method
Same as LED-124 (`knowledge/patterns/browser-check-with-local-user.md`): local Supabase only, headless Chrome over CDP, throwaway users, PostgREST-shaped errors injected with `Fetch.fulfillRequest`. This sweep used `sweep-a@example.test` (7 accounts incl. a PHP one and a credit card, **three loan accounts** — two with 4 purchases, one *legacy* loan with `loan_pay_period` set and `loan_due_days` null — a receipt in the local `receipts` bucket, 5 budgets, 2 goals, about 100 transactions). The credit-card monitor was captured in the **light theme** for the first time. Viewports 1920x1080, 1280x900, 1024x768, 768x1024 and 390x844. Light was the default; dark was viewed for Accounts (1280, 390), Login (1920, 390) and Budgets (1920). Everything else was viewed in light. Timezone emulation (`Etc/GMT+12`) proved the export file name uses the local date. One transaction ("Groceries #0") was deleted with the app's Delete and brought back with Undo, then re-created by hand when a test script stopped before Undo; the data is otherwise as seeded. Screenshots and scripts stay in the session scratchpad.

Two harness notes, not app findings: a few screenshots came out dark although the script asked for light (the harness sets the theme key right after the first page load; a fresh `system` default resolves dark in headless Chrome), and the click helper misses a button inside a smoothly scrolling dialog until the scroll settles.
