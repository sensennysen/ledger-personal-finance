## What went well
- **The new measuring tool proved itself on the old code first.** The `--hover` pass reproduced both ticket failures before the fix (4.26 and 4.4), so its PASS afterwards means something. Its first version hovered one row per class and missed the transfer row; running it on the old code showed the gap.
- **Measuring states the seed lacks found real bugs.** A backdated goal, a completed goal and a yearly budget over its limit were each added locally and removed afterwards. That is how LED-249 surfaced.
- **The forced-throw check measured every widget at both widths.** Its numbers caught two mistakes: a minimum height let short cards grow, and the trigger fired while skeletons were showing.

## What to change
- **Seed the states the UI branches on.** The seed has no completed goal, no yearly budget and no backdated goal, so no sweep can see those states. Each ticket here built them by hand.
- **A dev-only failure trigger must survive React's render retry and StrictMode's double effect.** Fail through state, set the flag when the timer fires, and render the trigger only under `import.meta.env.DEV`. Recorded in LED-243's retro.
