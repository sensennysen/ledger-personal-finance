Branch `epics-15-19` (the single working branch; no `phase-N` branch). Eight tickets, seven code commits: LED-196, 197, 198, 199, 200, 201, 204. LED-203 needed no change.

## What was built
- **LED-196** (`ede7bd9`). `signInWithGoogle` returns `{ started }`. On a failed start `LoginPage` shows `describeOAuthStartFailure(navigator.onLine)` in the existing error block and re-enables the button; on success the button stays disabled, because the browser is leaving. A `pageshow` handler re-enables it when Google's page is left with Back out of the page cache. Library and provider text is never shown.
- **LED-197** (`90f3c21`). `src/lib/accountDefault.ts` holds the picker's order (`pickerGroupOrder`, `compareAccountsForPicker`); `AccountCombobox` now uses it, so the form's default cannot drift from the list. The form reads `ledger_cache:<user>:accounts` once, only when `!navigator.onLine`, and opens on the first account the picker shows, with its currency. `useAccounts` is untouched. **Decision (asked, answered):** first account in display order, not "only when there is exactly one" as the ticket's suggested fix said; criterion (a) could not hold for several accounts otherwise.
- **LED-198** (`35e851f`). `useSavedFilters.remove` announces the delete on the notification surface with Undo; `restore` re-inserts the same `id` and `name`, so the `order(name).order(id)` read puts it back where it was. A failed restore says "It is still deleted" with the reason and Retry. Every caller of the hook gets it. The palette has no delete control, so none was added.
- **LED-199** (`210f75a`). `DashboardFirstRunChecklist` takes `loading`. While loading it keeps its rows, titles, descriptions and the footer sentence (none depend on data) and greys out the count and the buttons (button blocks are the real buttons' widths: 94, 78 + 77, 98px). It renders only when `shouldReserveChecklist` says it is certain to show: not dismissed and the pay cycle not confirmed. `isSetupComplete` is false for every such user, whatever the reads say. An unfinished row's second border pixel is now `ring-1 ring-inset` instead of `border-2`, so a row is the same height finished, unfinished or loading.
- **LED-200** (`8cc1eec`). The Home stat-tile skeleton now has the `mt-2` note wrapper the loaded tile always has. The Liabilities column skeleton is two groups (heading over a 148px card, a card then a loan) instead of three asset rows. The loan tracker footer and the Categories rules row put each grey run in a `span`; the rules skeleton is a count line over one row.
- **LED-201** (`be6ca22`). `public/theme-init.js` (classic script, first-party) sets `dark` and `meta[name=theme-color]` from `ledger-theme` and `prefers-color-scheme`, defaulting to dark, inside try/catch. `index.html` loads it after the theme-color meta. The CSP strings in `index.html` and `vercel.json` are unchanged and the test pins `script-src 'self'` in both.
- **LED-203** (no commit). Measured; the grid already equalises each row (see below).
- **LED-204** (`70fea5c`). `thinCategoryTicks(values, narrow)` in `chartTicks.ts`: every other label counted back from the newest. The net worth `XAxis` gets `ticks` and `interval={0}` below `sm` only. LED-174 added no x-axis helper (it only swapped a y-axis formatter), so this one is new.

## Backlog
- **Home widgets that appear only after load.** Credit Card Monitor and Budget Progress render only when data exists, so on a returning user's slow load Home moves down by 264.5px plus the gap. Not in LED-200's list; needs a ticket.
- **LED-199 partial states.** The skeleton models a user with nothing done. A user with some steps done sees it taller than the loaded card (demo at 390: three rows 173.5/131.5/173.5 loading against 95/115/154 loaded). A user who confirmed the cycle and is not finished gets nothing reserved. Returning users with cached data never see it (the data hooks read the cache first), so it is mainly the first visit on a device.
- **Remember the last-known presence.** Cache entries last 24 hours, so a user returning the next day sees skeletons. A per-device hint (did Forecast have items, did the net worth note show) would let LED-200's data-dependent sites be reserved without guessing. Not built.
- **LED-196 blocked redirect.** A blocked redirect to the provider is not catchable in the client. Only a failed `signInWithOAuth` start is.
- **LED-198 palette.** The palette's Saved filters group has no delete, so criterion (d) holds for the Activity dialog only.
- **LED-201 first frame.** No screenshot of the app's own first frame; a probe page proves the script, the real app proves the load order. The CSS still defaults `:root` to light, so with the script blocked (storage off, script failing) a dark user would see a light frame until React mounts.
- **Offline checks used a stub.** LED-197's offline path was exercised by forcing `navigator.onLine`, not by cutting the network.
- **Console errors seen, not investigated.** A 400 response and "Creating a worker from 'blob:…' violates … worker-src 'self'". Neither comes from this phase.
- **Skeleton contrast in light.** Grey runs on a white card are faint; the tokens were not changed.
- **LED-200 not viewed in light:** Categories and the loan tracker skeletons.
- **Local seed.** `supabase/seed.sql` was applied to the running local database to get the demo user (it only inserts). A temporary user and its data were created for measurements and deleted.
