## Decisions taken in the plan (approved with /apply)
- Amount means absolute size in the default currency (`amountInCurrency`). A row with no rate sorts last, by its own amount, never one to one.
- One sort menu with four options rather than a Date | Amount control plus a reverse button. It fits at 375.
- No hard time limit on reads. A hung (not refused) connection still waits.
- A cleared group the app holds in memory (appearance, preferences, Home layout, checklist, templates, install banner) reloads the page afterwards.

## Deviations
- **Profile and exchange-rate reads have the policy too.** The first measurement showed Budgets at 8.2 s, because it waits for both before its own read. With them, Budgets shows its error at 2.2 s. A side effect: on a cold failure, the "Couldn't load your profile" banner now also appears within about 1 s.
- **"Recurring entries already posted" is clearable.** The plan excluded it to avoid double posts. `patterns/browser-check-with-local-user.md` item 28 records that the database guards each post since LED-232, so the key is only a shortcut.
- **The notice rows moved to `src/lib/browserStorage.ts`** instead of being cross-checked against the page. This leaves one list and one wording. `legalPages.test.mjs` scans that file for keys and claims.
- **`useSubcategories` was not changed.** It never shows a load error, so a faster failure changes nothing.
- **The sort menu closes on a pick** (`closeOnClick`). Base UI radio items stay open by default.
- **The mobile month bar stays** while sorted by amount. The ticket names the rail, and the bar also holds the Select toggle.
- **Step 14 (the notice links to the card) was held back** as new legal wording (OD-5). It was approved later the same day and committed separately; the notice's last-updated date moved to October 4, 2026.

## What went well
- **Measuring before claiming LED-242 caught Budgets.** Four pages passed, and Budgets did not. The gate was two context reads, not its own.
- **Moving the notice rows into `src/lib`** let one file serve the legal text, the clear logic and the key-scan test.

## What to change
- **The in-page `fetch` override (pattern item 22) cannot test a first load.** Mounted hooks don't refetch on in-app navigation, and a reload drops the override. Use CDP `Network.setBlockedURLs` for anything that needs a cold load. This is now in `patterns/first-load-fails-fast.md`.
- **A Base UI menu closes when the in-app browser takes a screenshot.** Drive menus with dispatched pointer events and read `[role=menuitemradio]`, as pattern item 24 says for tabs.
