# Epic 22 · Phase 2 — Personal data in the database (decision C) — retro (2026-10-06)

Branch `epic-22`. Six tickets: LED-263 to LED-268. Five feature commits and two validation fixes. LED-268 is written but **not committed**: its legal wording waits for the owner's approval (OD-5).

## What was built
- **LED-263** (`29c61e5`). `profiles.preferences jsonb not null default '{}'` holds only the changed keys. `src/lib/preferences.ts` merges the defaults and checks each value. `merge_profile_preferences(p_patch, p_only_if_empty)` (SECURITY INVOKER) merges per key. `usePreferences` now reads the profile; the module singleton is gone. `AuthContext` gained `patchProfile`, `setPreferences` and `syncSettings`: a change shows at once and is sent at once, or on `online` when offline. A failure shows as a new `settings` auth error with Retry. The one-time upload drops `accGroupOrder`, because `profiles.account_group_order` already holds it.
- **LED-264** (`b33cc7b`). `profiles.dashboard_hidden_widgets jsonb`, null until written. It lists the hidden widgets, so a new widget shows by default. Constants moved to `src/lib/dashboardLayout.ts`. Hiding and reordering save through `patchProfile`; the old order write dropped failures silently. Both old keys are removed.
- **LED-265** (`422caab`). `setup_checklist_dismissed_at` and `pay_cycle_confirmed_at` (`timestamptz`, null until done). The hook reads the profile. The old key had no user in it, so this also ends a cross-user leak.
- **LED-266** (`cfeec1c`, fix `d0224e1`). `card_reminders_sent (user_id, reminder_key, sent_on)` with RLS. A reminder shows only when this device's `upsert … ignoreDuplicates … select()` returns its row. Each check deletes rows older than 60 days. Offline, the check does not run.
- **LED-267** (`6ca7c23`, fix `8eefd69`). `thirteenth_month_selections` records that a year was saved, so a saved Clear is not read as "never picked". `thirteenth_month_picks` cascades from `transactions`. `set_thirteenth_month_picks(p_year, p_ids, p_only_if_absent)` replaces a year in one statement and drops ids the caller does not own. `useThirteenthMonthPicks` reads through `readWithPolicy` and `readAllPages`.
- **LED-268** (uncommitted). `isPersonalKey` and `forgetPersonalBrowserCopies` in `browserStorage.ts`. Sign-out and account deletion remove every personal key, including a previous user's per-user keys. Drafted: the "Removing them" and "Notifications" text on the Cookies and storage page, the settings line in Privacy Policy §1, and the data-deletion list and "On this device" text. `LAST_UPDATED` is October 6, 2026.

## Issues
- **[FIX NOW, fixed] LED-266: the old key never moved with reminders off.** The upload ran inside the check, which needs reminders on and permission granted. It now runs once on its own (`d0224e1`).
- **[FIX NOW, fixed] LED-267: a failed picks read showed "$0.00" under "no estimate yet",** with clickable checkboxes that did nothing. It now shows a dash and the controls are disabled until Retry (`8eefd69`).
- **LED-264 was first committed with four failing tests.** `widgetBoundary` and `dashboardWidgetOrder` read `DEFAULT_WIDGET_ORDER` from the hook's source, and the constant had moved. Fixed by an amend before pushing. Lesson in the new pattern, item 8.
- **Plan change:** save failures for profile settings go to the auth error banner, not a toast. `AuthContext` sits outside `NotificationProvider`.
- **In-memory session after `localStorage.clear()`.** Clearing storage on a signed-in tab did not sign it out, and the next navigation wrote a fresh token. Plant keys on `/login` after a reload, not on a live session.

## Backlog
- **A setting changed offline is lost on a reload while still offline.** It is kept in memory only; the cached profile shows it, but nothing sends it. The plan accepted this.
- **The first device to sign in after the deploy decides** whether a browser's old preferences, layout or checklist upload. A later device's old keys are dropped if the account already has values. This matches LED-257's choice.
- **Card reminder claims on two real devices** were checked at the REST level only, not with two browsers showing OS notifications.
- **From-empty migration replay** only runs in CI's `db` job. `pnpm db:reset` would wipe the owner's local data.
- **Release checklist B:** five migrations (`20261006120000` to `20261006120400`) reach the hosted database before the merge. `pnpm db:push:remote` runs only when the owner asks.
- **Legal drafts** for LED-268 (and the "(older copy)" storage rows from LED-263 to LED-267): owner approval (OD-5).
