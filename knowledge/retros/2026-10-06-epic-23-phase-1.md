## The rule for LED-278 (c)
A pending value is sent only while the account still holds the value it replaced (`base`). After every profile read, `dropStale` removes two kinds of change:
- **Already stored:** the account holds the pending value, for example sent before a reload.
- **Superseded:** the account moved away from `base`, because another device saved a newer value. That newer value wins.

Values compare by their JSON. The read and the write are separate requests, so a change from another device that lands between them is still overwritten. The window is one request long.
