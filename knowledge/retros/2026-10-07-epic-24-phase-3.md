# Epic 24 · Phase 3 — Durable, shared queue — retro (2026-10-07)

Branch `epic-24`, not pushed. Four tickets in build order: LED-303, LED-302, LED-318, LED-305. One commit each, two validate fixes and these docs. This phase changes only the client, so it has no migration and needs no release checklist B.

Owner decisions in /plan (the plan's recommended options, approved with /apply):
- **D1 · LED-303 moves to IndexedDB.** It does a one-time move from localStorage.
- **D2 · LED-302 uses Web Locks, with no lease fallback.** Without `navigator.locks` the drain runs unlocked and relies on idempotent inserts (LED-298) and revisions (LED-297).
- **D3 · No IndexedDB means no offline saves.** The save returns the storage error, and the offline banner says so in red.

## What was built
- **LED-303** (`4810709`, validate fix `3a985bd`).
  - `src/lib/queueStorage.ts` keeps the queue as one ordered record in the database `ledger_offline_queue`. `mutateStoredQueue(fn)` reads, changes and writes it in one readwrite transaction, and resolves only when the write commits.
  - Writers return `{ error }` and do not throw: `enqueue`, `enqueueMany`, `editQueuedInsert`, `keepMine` and `retryFailedItem`.
  - Every offline path in `useTransactions` and `useMonthCycle` waits for the queue write before updating the list or balances. The queue is written first, so nothing on screen ever has to be rolled back.
  - Synchronous reads (counts, `listQueue`, `revisionFor`) use a snapshot of the last commit.
  - `loadQueue()` moves a localStorage queue in once (`mergeLegacyQueue`, by id) and removes the old key after the move commits.
  - Drain deps are now an async `readQueue` / `mutateQueue`. `setResolvedReceipt`, the closing merge and `discardFlagged` each run inside one transaction.
  - Validate fix: `writeCache` returns false on a quota error, and `updateTransactionCache` tells other instances to reload only when the write landed.
- **LED-302** (`05cc851`, validate fix `9098c22`).
  - Every commit posts `changed` on the BroadcastChannel `ledger_offline_queue`, and other tabs re-read the queue.
  - `drainQueue` holds the Web Lock `ledger_queue_drain` (`exclusive`), so a second drain waits and then sends only what is left.
  - Validate fix: a drain that saved rows posts `synced`, and other tabs refresh their lists (`subscribeRemoteSync`).
- **LED-318** (`b4f42b6`). An offline import is one `enqueueMany` write, one list update and one balance pass.
- **LED-305** (`63ce75e`).
  - `syncReadiness.ts` adds `shouldDrain` and `retryDelay` (5 s, 30 s, 2 min, then stop).
  - `NetworkStatusProvider.autoSync` runs after the queue loads, on `online`, and on focus or when the tab becomes visible.

## Found
- **A failed cache write made every list reload the old cache.** `writeCache` swallowed a quota error, and `notifyTransactionsRefresh` then reloaded the stale list over the new row in every instance, including the one that saved. The plan included `writeCache` returning a boolean, but /apply missed it. Found live and fixed (`3a985bd`).
- **The tab that did not drain kept stale rows.** The broadcast updated its counts but not its lists. Fixed with `synced` (`9098c22`).
- **Under Vite, a console `import()` is a second copy of a module.** The first two-tab run enqueued through a copy without the app's `?t=` suffix, so the app saw the items only after the broadcast. Use the app's URL (pattern updated).

## Backlog
- **Balances exclude a stored change when the cache is full.** The row shows as queued, but the account balance keeps the last cached server value until the sync. It is never invented, but it is stale.
- **A receipt that can't be queued after an online save is only logged.** If the upload fails and the queue cannot store the receipt job, the transaction stays saved without its receipt, and only the console says so (`queueReceipt`). Showing it needs a surface for a successful save with a warning.
- **Keep mine and Retry give no message when the queue can't be written.** The item stays flagged as it was. The review sheet has no error line.
- **The import screen was not driven offline.** It is capped at 5,000 rows, and the 10,000-row check ran at the queue layer.
- **A tab can miss an item another tab enqueued while online.** `autoSync` decides from the snapshot. If an item arrives by broadcast just after `online`, it waits for the next trigger (focus, visibility or a retry). The app enqueues only while offline, so this showed up only in the test.
- **Retries do not reset on Sync now.** They reset on reconnect, focus and when the tab becomes visible.
- **No lease without Web Locks (D2).** Two such tabs draining at once could flag a false "edited" conflict for an update.
- **Pre-existing console error.** The `worker-src 'self'` blob worker error is still there, unrelated to the queue.
