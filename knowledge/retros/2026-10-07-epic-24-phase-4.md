## What was built
- **LED-313** (`06b7c6a`). A failed contribution keeps the dialog and the amount and shows `FormError`.
- **LED-312** (`ce0d0fa`, validate fix `6ef0be8`).
  - `add_goal_contribution(goal, amount, op_id)` is SECURITY INVOKER. It locks the goal, records `op_id` in `goal_contribution_ops`, then increments in SQL. A replayed op id adds nothing.
  - The client makes one op id per opened dialog. The ops policy also requires the goal to belong to the caller.
- **LED-310** (`4048308`). `src/lib/cashFlowForecast.ts` converts each recurring item into the base currency. An unrated item is left out of the totals, shown in its own currency, sorted last and named.
- **LED-311** (`f1052a4`). `src/lib/goalContributions.ts` converts the linked total into the goal's currency, on the goal card. `useSavingsGoals` also feeds the export page, which has no rates provider.
- **LED-314** (`e175b35`).
  - Ownership checks for: transaction `goal_id`; rule `category_id`; card payments (the payer's own card, the payer's own transfer to that card, and an amount that matches the transfer when the link is made); 13th-month pick `transaction_id`.
  - A repair runs first, with a notice for each count.
- **LED-315** (`066f8e5`). Bulk category changes clear `subcategory_id`. Two deferred constraint triggers check the parent and child at commit, so `merge_category`'s statement order still passes.
- **LED-316** (`a656cac`). `trg_account_currency_locked` refuses the change when the account has history. `useAccountHistory` in `AccountForm` disables the selector with a hint and stays locked if the check fails. This changes the plan: no `useAccounts.accountHasHistory` passed in by callers.
- **LED-308** (`67ad103`). `readAllPages` with a total order for card payments, loan purchases and all subcategories. `src/lib/idBatches.ts` batches `.in()` filters at 200 ids.
- **LED-309** (`f6baa07`). `useAccounts({ includeArchived })` has its own cache key. The export uses it; pickers stay active-only.

## Found
- **`seed.sql` failed on an empty database since LED-296.** The transfer trigger already records the card payment, so the seed's insert duplicated it. CI's `db` job would have failed. Fixed in `39822b7`. Found with `patterns/replay-migrations-into-a-scratch-database.md`.
- **A foreign key ignores RLS.** The first ops policy let B record an op on A's goal. A new table with a user-owned reference needs the owner in `with check` or a trigger.
- **`set local role anon` keeps the earlier `request.jwt.claims`**, so `auth.uid()` was still B. Set the claims to `{"role":"anon"}` as well.
- **A per-row parent/child check would break `merge_category`**, which is only consistent at the end. Use `deferrable initially deferred` constraint triggers.
