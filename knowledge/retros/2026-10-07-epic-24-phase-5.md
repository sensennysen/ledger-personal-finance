## What was built

  - `src/lib/entityQuery.ts` (pure):
    - `entityKey(userId, entity, params)`.
    - `entityQueryOptions`: the device copy is `initialData` with `initialDataUpdatedAt: 0`, so a mount always refetches. A read runs in background mode when a copy exists. The copy is written only by a read that succeeded and was not cancelled. A failure throws an `EntityReadError` carrying the sentence.
  - `useEntityQuery` keeps the old hook return shape.
  - `useAccounts`, `useCategories`, `useSavingsGoals` and `useCreditCardPayments` were moved onto the store.
  - The `QueryClientProvider` wraps `AuthProvider`. `forgetQueries()` cancels and clears the store on sign-out, account deletion and a user switch (LED-295).
- **LED-304** (`13bb217`)
  - The transactions read is keyed by every filter, passes `signal` to `.abortSignal()`, and passes `readAllPages` `isCancelled`.
  - An uncached filter shows loading instead of the previous filter's rows.
  - `inFlightRequest.ts` / `dedupeAsync` deleted.
- **LED-307** (`b9c03fc`)
  - `src/lib/readState.ts`: a paused read with no data is unavailable, with the message "You're offline and this device has no saved copy of {list}. They load when you're back online." `useEntityQuery` returns it as `error` with `offline: true`, so `resolveLoadState` gives `error`.
  - The store starts from `navigator.onLine`.
  - `useExchangeRateRow` was moved onto the store.
- **LED-306** (`29e258c`)
  - `src/lib/invalidation.ts`: `INVALIDATES`, `invalidateEntities`. `invalidateAfterWrite(source)` refetches every mounted read of the affected entities and marks idle ones stale.
  - `cacheEvents.ts` is now one contract, `registerEntityListener` / `notifyEntityChanged`. It is used by `useBudgets`, `useLoanPurchases` and the card payment history.
  - A queue drain or resolve (`notifySyncListeners`) invalidates `sync`.
  - Offline account deltas update both account reads.
  - Removed: the AppLayout synced listener, the page-level card refresh calls, and the card-detection lookups after an import or recurring post.

## Decisions and lessons
- **Copy versus store.** TanStack is the in-memory store; `dataCache` is still the device copy, because the offline queue and optimistic writes depend on its keys. A persister would have duplicated it and broken the sign-out clearing.
- **TanStack's online state at startup.** `onlineManager` only hears `online`/`offline` events after load. Without seeding it from `navigator.onLine`, an app opened offline tries its first reads and shows "Couldn't reach the server" instead of the offline state.
- **Paused reads need a mounted client.** A paused read resumes only on a mounted client. `QueryClientProvider` mounts it; the unit test calls `qc.mount()` itself.
- **Reading the store from the browser.** Use `import('/src/lib/queryClient.ts')`. For `onlineManager`, use the exact `?v=` deps URL, or you get a second instance. Pattern updated: `knowledge/patterns/hook-instances-do-not-share-state.md`.
- **Extra reads from staleTime.** Opening the transaction form after 30 s refetches accounts and categories (refetch on mount when stale). This is expected; before the store, every mount read again.

## Backlog
- **LED-304 live.** Reproduce the filter race in the UI with a throttled request (Activity filters are locked until setup is finished for the demo user).
- **LED-306 edit and sync live.** Edit a transaction from another surface with Home mounted, and drain a queued offline write with Home and a filtered list mounted. This needs real network emulation: the in-app browser can't set `navigator.onLine`, which the write paths check.
- **LED-307 wording on pages.** 13th Month (and any page with its own read-error sentence) ignores the hook's `error`, so the offline message never shows there. Either render the hook's error or branch on `offline`.
- **Dead code.** `registerSyncedListener` (`src/lib/offlineQueue.ts`), `importedCardPayments` (`src/lib/importTransfer.ts`) and `generatedCardPayment` (`src/lib/cardPayment.ts`) are no longer used by the app; only their tests use them.
- **Reads not on the store.** `useBudgets` (cycle state, keep-previous-data) and `useLoanPurchases` still read on their own and refresh through `registerEntityListener`. Moving them is follow-up work.
- **Bundle size.** `@tanstack/react-query` adds about 13 kB gzip. Not measured against the previous build.
