## What was built
- **LED-319** (`7aac8a7`)
  - Four pgTAP files in `supabase/tests/database/`, 39 checks:
    - `01_tenant_isolation`: anon and user B see no row of A in any user-owned table (found from `pg_catalog`) or A's profile. LED-294 loan values are null for anon and B and correct for A.
    - `02_cross_owner_writes`: B's references to A's card, goal, category, card payment, transfer and transaction are refused (LED-296, LED-312, LED-314). anon can't insert.
    - `03_money_invariants`: LED-296 payment on insert, replay, edit, delete and balances; LED-312 replay and a negative amount.
    - `04_reference_consistency`: LED-315 subcategory parent, including `merge_category` at commit; LED-316 currency lock.
  - `supabase/tests/concurrency.sh`: two `psql` sessions for concurrent card payments and goal contributions (4 checks).
  - The `db` job runs both after the replay. `pnpm db:test` runs them locally.
  - `tests/transactionsRace.test.mjs` gained a case: sign-out while a transactions read is in flight stores and shows nothing.
- **LED-320** (`24fb2b4`)
  - `src/types/database.ts` is generated (`pnpm db:types`), and `createClient<Database>` uses it.
  - Entities are `Entity<'table', Loose, Narrowed>` in `src/types/index.ts`. Reads narrow with `.overrideTypes<…>()` instead of casts; joined selects pass `{ merge: false }`.
  - Writes take `Columns<'table', Entity>`. JSON writes are cast `as Json` at the call.
  - `DrainClient` is a typed structural interface instead of `any`.
  - `src/types/databaseContract.ts` fails the build if a wrong column, table or RPC argument compiles. The `db` job diffs the generated types.
- **LED-317** (`e865d7b`)
  - Every page but sign-in, and the signed-in shell (`AppLayout`), is `React.lazy`. Public routes wait on the auth spinner; app pages wait on a skeleton inside the layout.
  - jsPDF loads in the PDF handler and `ImportCSVDialog` on first open. A failure notifies with a Reload action.
  - Chunks those imports start are named `deferred-*` (`vite.config.ts`). They are left out of the precache and cached on first use (`ledger-deferred-chunks`).
  - `ErrorBoundary` recognises a chunk failure (`isChunkLoadError`) and says why, with Reload. `main.tsx` reloads once per session on `vite:preloadError`.

**Changed from the plan**
- LED-319:
  - The LED-315 and LED-316 checks got their own file. On the old chain, the first missing function aborted file 03, so they never ran.
  - The planned `00_helpers` file isn't needed: each file sets up its own users.
- LED-317:
  - The planned retry helper (re-create `lazy` after a failure) was dropped. Chrome keeps a failed `import()` for the life of the page and never requests it again, so recovery is a reload (`patterns/failed-chunk-import-needs-a-reload.md`).
  - `AppLayout` was split too: pages alone left the entry at 593 kB, over the warning.
  - Deferred chunks are named by the dynamic import they start (`facadeModuleId`) rather than by `manualChunks`: they also carry shared Babel helpers.
- LED-320: `SplitRpcLine` became a `type`, which makes it assignable to `Json` without a cast.

## Found
- **Chrome never retries a failed `import()` in the same page.** It made no request on the second attempt. Only a reload fetches again.
- **A scratch replay has no Supabase grants.** `authenticated` gets "permission denied for table" until the platform's default grants are added (`patterns/replay-migrations-into-a-scratch-database.md`).
- **The CLI's type generation doesn't need the `postgres-meta` service.** It runs its own container, so CI's `-x postgres-meta` is fine.
- **pgTAP assertions work after `set local role authenticated`.** No helper functions or extra grants are needed.
- **The old row types claimed full joined rows** (`Transaction.category: Category`), while queries select a few columns. `{ merge: false }` keeps that as it was; it is not new.
